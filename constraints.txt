# constraints.txt -- the supply-chain pin (adopted 2026-08-08).

# pyproject.toml states INTENT (floors, per its own philosophy); this file
# states the exact versions CI installs, frozen from a venv that ran the
# full suite green. The nightly runner holds the LLM API key in its env,
# so an unpinned `pip install` meant any transitive release could reach it
# the same night. CI installs with `-c constraints.txt`; versions move only
# by editing this file (Dependabot proposes bumps weekly -- merge = bump).
# Regenerate after a deliberate upgrade: pip freeze --exclude-editable > constraints.txt
# (then re-add this header) and run the full suite before committing.
#
# PLATFORM: this file is the union of two dependency trees, because the one
# that matters is the runner's, not the laptop's. torch pulls its CUDA stack
# (cuda-*, nvidia-*, triton) only on Linux, so a freeze taken on macOS never
# names those packages and CI installed ~19 of them unpinned every night --
# the exact exposure this file exists to remove. The CUDA versions below were
# captured from an ubuntu-latest run on 2026-08-09. A macOS `pip freeze` will
# not reproduce them, so regenerating on a Mac must ADD to this file, never
# overwrite it. Listing a package that a given platform never installs is
# harmless: a constraints file caps versions, it never causes an install.
