The Pulse · Story of the day

Fine-tuning agents on individual turns fails the full-workflow test

Agent fine-tuning that lifts turn scores leaves workflow completion unchanged, at under 11% success.

An arXiv preprint tests supervised fine-tuning on Qwen3 and Gemma 3 models across multi-turn customer-support workflows. Turn-by-turn scores improve for every model after fine-tuning; autonomous workflow completion does not, reaching at most 10.4% success. Before fine-tuning your next agent, define end-to-end task completion as the primary eval, not turn accuracy.

An OpenAI engineer's four rules for keeping production agents honest

Model benchmarks were the production reliability check; the harness around the model is.

Vinoth Govindarajan (OpenAI infrastructure) argues production agents break not on hallucination but on four architectural failures: state without a single owner, unordered concurrent writes, unbounded execution authority, and actions proved only by transcript. The transcript is not the receipt. Before your next agent architecture review, which of these four invariants does your harness actually enforce?

Scoring each tool call misses whether the agent finished the work

Call-level accuracy was the agent eval standard; task completion is now the release gate.

Single-call accuracy is necessary but not sufficient: a valid tool call still fails if the underlying task didn't complete. NVIDIA's technical guide separates step-level scoring (where did the chain break?) from end-to-end outcome scoring (did the work finish?). Adopt end-to-end outcome scoring as your release gate; keep step-level traces for debugging.

Alibaba's code-review tool uses determinism where AI would waste tokens

OpenCodeReview (Apache-2.0, Go CLI) keeps file selection, rule matching, and comment positioning deterministic, reserving the language model only for analysis.
