The Pulse · Story of the day

Reverse-engineering Claude Code reveals the design rules agentic systems need

Researchers reverse-engineered Claude Code's source code, mapping five design values through thirteen principles. The core is a simple loop; the real complexity sits in a seven-mode permission system around it. The paper triangulates its reading against two independent open-source agents, OpenClaw and Hermes Agent, though it remains one research team's analysis. Agentic coding systems are already structuring human authority as a first-order constraint, not a safety layer bolted on after the fact. Where yesterday's Pulse showed agents hiding the evidence they never used, today's shows the same systems making human authority a design primitive -- oversight is shifting from an audit problem to an architectural one.

The Big Picture

3 stories

Safety is an engineering problem. Today's research treats alignment failures as fixable at the infrastructure layer: through provenance checks, instruction tuning, and a hard look at how tokenisation fragments safety. The implication is that governance now has specific levers to pull, not just principles to endorse.

Character-level text tricks bypass safety filters in most open models tested

BPE tokenisation fragments safety-critical words into sub-pieces, and none of the 30,000 alignment examples across three public datasets contained intentionally fragmented inputs. Across five open model families, simple character-level perturbations flipped refusals on 80-100% of harmful prompts; 48% produced genuinely harmful outputs. No code is public yet. If a perturbation this simple flips refusals across five open model families, how much of the published refusal-rate literature still describes a defence that holds?

Provenance checks cut AI agent tool errors from 42% to under 2%

The weak point in deployed AI agents is unverifiable tool calls. ProvenanceGuard checks each proposed action against traceable evidence in the agent's context before execution, cutting error rates on misaligned actions from 42.9% to 1.8% on one benchmark. No code is public. If provenance tracing can cut misaligned tool-call rates this sharply, what does that ask of the liability and sign-off frameworks now being drafted around autonomous agents?

SkillOpt trains an agent's instruction file without touching the model

SkillOpt treats an agent's instruction file as a trainable parameter, running a forward-backward-update loop in text space while the underlying model stays frozen. Across 52 benchmark-model combinations, it was best or tied-best in every cell, lifting one model's average score from 58.8 to 82.3. No code is public yet. If instruction files can be tuned into gains like this while the model stays frozen, where should teams draw the line between prompt engineering and training?

Hands-On

3 stories

Bench before you budget. Today's pattern is mixed provenance: one genuinely independent benchmark, one vendor trace tool, one workflow tip. Treat the independent score as signal; hold the rest until you can replicate it on your own documents.

Vercel now exposes full agent traces via its CLI and inspector tools

Vercel's eve agent framework now auto-ingests traces on deployment, surfacing reasoning steps, tool calls, and token usage through four new CLI commands (vercel agent-runs inspect, trace, list, projects) and matching MCP tools. Single-vendor source, no independent benchmarks. If you're already running eve on Vercel, pull vercel agent-runs trace on your next production run before filing a bug report.

The best AI systems score under 60% on real Office documents

Office Comprehension Bench (OCB) is the first public benchmark testing language models on native Word, Excel, and PowerPoint files. The strongest frontier model scores only 59.3% on expert-level document reasoning; pushing it to think harder barely moves the needle. Dataset and tooling are public, though scoring runs on the paper's own ensemble of LLM judges, with no independent replication yet. Run OCB against your document pipeline before signing a processing vendor.

Claude Code tip: let the agent decide when to write tests

The Claude Code team's tip: give Fable a goal, not a rulebook. Instead of "run tests only for large features," tell it to use its own judgement. A second trick routes smaller coding tasks to cheaper sub-models, preserving the top-tier model for review and synthesis. Single-source, practitioner-reported. Currents

1 item

One current worth watching. A thin day beneath the surface, but not an empty one. The undercurrent is agent frameworks hardening their primitives -- skills, sandboxes, subagents -- into named infrastructure. One vendor's move is not yet a trend, but it is the direction to watch as scaffolding choices start to set.

Vercel's agent framework treats skills and sandboxes as first-class infrastructure

Early signal: Vercel's eve framework, grown from building its v0 vibe-coding product, packages four primitives as first-class infrastructure -- skills (portable knowledge to correct outdated model behaviour), sandboxes for secure code execution, subagents, and resumable runs. Single-source interview; no independent benchmarks; the shipping CLI that traces these agents in production sits in Hands-On above. If this primitive set becomes the default shape of agent frameworks, scaffolding choices made against it now will age well; if it stays one vendor's house style, it is a preview rather than a standard.
