Ollama rejects some models before inference, making benchmark scores meaningless

Local tool-use benchmarks measured model capability; the serving layer was the hidden variable all along.

An arXiv preprint finds that in Ollama, Phi-3 and Gemma-3 are rejected before inference runs; the harness logs this as a model non-call, reporting 0% fidelity. Turn-pooled versus per-instance estimates differ by up to 55 points across stacks. The serving layer, not the model, is where local tool-use performance is decided.

The Big Picture

4 stories

Governance and interpretability are moving in opposite directions simultaneously: one architectural shift closes the only readable window into agent reasoning while two separate developments hand regulators and institutions their first credible tools for inspecting what models actually do internally.

AI agents' only readable audit trail is now under architectural threat

Chain-of-thought is the sole validated window into agent reasoning; competing labs are building around it.

Redwood Research argues that latent-reasoning architectures, such as COCONUT and full-bandwidth transformers, would let agents reason for orders of magnitude longer without producing any human-readable chain of thought. That removes the only tool that currently makes agent cognition auditable. Does your governance framework still hold if the reasoning traces it depends on simply cease to exist?

Regulators can now audit what a finance language model actually thinks

Opacity was the deployment barrier for language models in regulated finance; mechanistic interpretability removes it.

Tatsat and Shater apply mechanistic interpretability to Gemma 2 and GPT OSS, surfacing internal features tied to bias, hallucination, sentiment, and trading signals. The technique steers and monitors model internals rather than treating outputs as a black box. Before citing auditability in your next regulatory submission, which internal features does your model-risk framework actually specify?

Each story today exposes a gap between what a standard check reports and what a real workload reveals: health checks that miss slow GPUs, local tests that miss live failures, Kubernetes that masks scheduling limits. The practical work this week is instrumentation, not capability.

A healthy GPU cluster can still silently fail a real training job

Cluster operators now have a named suspect node before the workload stalls, not after a customer ticket.

NVIDIA's open-source Kubernetes controller, NVCRE, runs actual distributed workloads across node groups and names exactly which node failed each test. A 512-GPU job can underperform despite every health check passing; one slow GPU or misconfigured network path is enough. Deploy NVCRE against your next cluster bring-up and get a failed-node report before production lands.

Open-source tool converts any research paper into a runnable agent

Repo archaeology was the hidden cost of published methods; Paper2Agent makes the paper itself the runnable artefact.

Paper2Agent (open-source, published in Nature) feeds a paper and its codebase to an orchestration system that auto-generates tested tools, then packages them as a conversational agent. For AlphaGenome, it produced 22 validated tools on a laptop for under $15. Clone the repo and run it against a paper you've been meaning to implement before writing the scaffolding yourself.

Coding agents pass local tests but fail one-in-three live serving checks

Local test suites were the coding-agent quality bar; live serving failures expose a 23-point gap.

SWE-Serve, a benchmark from NVIDIA built with the SGLang team, tests coding agents on real inference-serving code. Across 19 tasks with live-serving checks, pass rates dropped from 69.4% to 45.9% when those checks ran. The benchmark, paper, and leaderboard are public. Run SWE-Serve against your next agent eval before trusting local scores in production.

Currents

3 items

Three preprints this week are quietly rewriting what agent evaluation actually measures, shifting attention from whether a task finished to how well decisions were made along the way. All three remain early and single-source, which is precisely why they sit here.

Top AI agents pick the right fork only 60% of the time

End-to-end task scores were the only agent quality signal; mid-run decision accuracy is now benchmarked and trainable.

Existing benchmarks measure whether an agent finishes a task; Taste-Bench measures whether it chose well along the way. Across 502 automatically mined decision forks, the best of 14 frontier models scores 59.7% (random baseline: 25%). Dataset and code are public. Distilling hindsight into a student model lifted SWE-bench Pro success from 14.6% to 33.7%.

A smart sampling method cuts language model eval costs to under 2%

Benchmark runs were priced as all-or-nothing; a principled stopping rule makes 98% of them optional.

Exhaustive benchmarking of every model configuration is the hidden tax on evaluation pipelines. GittinsEval, an arXiv preprint, applies a Bayesian bandit policy to decide which configuration to test next and when to stop, reaching near-zero error using just 1–2% of full benchmark items. The preprint and its code are public, covering five model-selection scenarios on standard benchmark datasets.

Agents track long tasks better when they write their own state

Showing agents an accurate checklist was the assumed reliability fix; agent-written ledgers beat it.

An arXiv preprint tests four ways task state reaches an agent: raw transcript, checklist, state-machine directives, or an enforcement gate. The agent-written ledger beats an accurate checklist the agent is shown. Enforcement lifted one model's task-completion rate from 0.39 to 0.54, but hurt a smaller model where the gate's judgement was wrong. The ledger method is public in the preprint.
